## 功能与改动边界

原 Java 业务实现、策略公式、压缩算法、模型文件、网关、接收协议、图表组件及 API 客户端均保留。新增内容是两种页面组合、模式入口、布局和启动配置。发送/接收的业务脚本沿用原代码；原完整监控、效果和接收页面继续可用。

安装时没有关闭 TLS、包完整性或软件包签名检查。JDK 与解压器通过已验证签名的 Debian 索引下载；npm 镜像地址仅在临时安装目录替换为官方源，原版本和 integrity 校验保持不变。Java 编译使用完整 JDK，解决了初始运行时缺少目标版本编译支持的问题。

图像证据：adaptive-completed.png、prediction-completed.png 是完整文件传输后截图；adaptive-overview.png、prediction-overview.png 是最终页面检查截图。未完成任务时的原空曲线、指标 `—` 等行为没有替换成模拟页面数据。

## 未验证及原有行为

- Windows 批处理启动器尚未在 Windows 实机验证。它们调用已在 Linux 验证的共用 Node 启动逻辑。
- 未连接真实 RabbitMQ Broker；消息队列原源码及原回归测试保留并通过，实际队列工作流需提供 Broker。未进行跨电脑网络或防火墙验证，接收流程在不同本机端口的真实服务间验证。
- 大于 1 GB 的上传分片路径、长时间预测精度、实际部署并发能力未作额外负载测试；对应原实现保留，不据此声称已全面验证性能。
- 原任务内部具有传输耗时建模；无外部遥测时使用原动态采样。跨电脑接收仍在完成恢复包后投递。本次没有把模型数据重定义为真实线路测量，也没有改动预测健康或精度算法。
- 原上传后的选中项可能暂时保持上传前值；测试中通过原下拉框确认文件。本次没有修改原业务脚本修复该原有行为。
