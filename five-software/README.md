# 五个独立软件交付说明

基于上传的 DataCompress_System 分卷源码完成职责拆分。每个目录可单独复制到另一位置、单独构建与启动，没有公共源码模块或跨项目启动依赖。原上传文件保持原样。

| 工程目录 | 软件名称 | 默认端口 |
| --- | --- | --- |
| 01-network-monitor | 多源网络传输状态实时监测软件 | 8101 |
| 02-adaptive-strategy | 自适应数据压缩策略分析与优化软件 | 8102 |
| 03-rate-prediction | 基于时序特征的网络传输速率智能预测软件 | 8103 |
| 04-compression-library | 多算法无损数据压缩方法库管理与可视化软件 | 8104 |
| 05-transfer-manager | 数据压缩传输任务交互与全流程管理软件 | 8105 |

## 最快开始

安装 Java 17+，解压某个软件运行包，双击 `start.bat` 或执行 `sh start.sh`，在浏览器输入其 README 中的地址。每个软件都已包含 `app.jar`，不需要安装原系统的 Node 网关或 Vue 构建工具。

“全部源码包”不含 JAR，需要 JDK 17+ 与 Maven 3.9+。各软件的独立交付包同时包含源码与可运行 JAR。

## 拆分原则和代码重复

原系统 41 个 Java 源文件按功能唯一分配，详细路径见 `code-ownership.json`。原 UI 与网关聚合了跨功能接口，因此没有复制整套 Vue/Node 单体到每个项目；重建了五套各自服务于对应功能的静态中文界面与独立 API。

已检查所有自有 Java 源文件：即使把不同包名统一后，唯一完整重复的文件也是 9 行 Spring Boot 启动入口；核心业务文件没有完整重复。业务代码按职责归属，没有跨项目源码引用。通用页面布局、HTTP/文件处理惯用写法、启动基础结构和第三方框架依赖仍有相似内容，不宣称逐行或任意算法评估下重复率为零。

## 与原系统的行为差异

- 多源监测通过显式 HTTP 遥测接入，默认不模拟；不自动连接示例 MQTT/RTSP 地址。
- 策略软件独立支持 JDK 画像实测，并能离线导入算法库多算法画像。结果为策略估算，不代表已经执行传输。
- 预测软件使用原权重，保留回退与反馈机制，没有重新训练模型或保证实际精度。原训练脚本是提示骨架。
- 原生无损算法实现集中在算法库软件。
- 任务软件具有真实 ZIP/HTTP/ACK/恢复校验流程和可恢复历史，独立模式采用 ZIP。原单体跨功能的实时 LSTM 多算法联动不在五个项目中重复复制；暂停、取消、重试的具体边界见任务软件 README。

## 验证与交付内容

15 个单元回归测试全部通过，算法库中的 1 个回归用例覆盖 10 种算法；另有 42 项独立启动、功能、浏览器和重启检查通过。检查清单、源码统计、截图及各工程测试结果见 `validation`。

`validation/verify.py` 可单独运行五个可执行 JAR 的 API 检查；如果使用 `--browser`，需另行提供 Node、Playwright 和 Chromium。它是交付包验证工具，不是软件运行依赖。调用示例：

```sh
python validation/verify.py
```

第三方框架和 native 库会出现在各可执行 JAR 中，这是独立部署所需的运行依赖，不是五份业务源码复制。当前测试平台为 Linux x86_64；用户现场跨电脑网络与 Windows 原生运行尚未实测。
