# 拆分交付验证报告

## 实际结果

- 5 个独立 Maven 工程均完成 `package`，编译目标为 Java 17。
- 15 个单元回归测试通过：失败 0、错误 0、跳过 0。
- 42 项启动、实际 API、浏览器交互和任务重启检查通过。
- 每个软件仅带自身 JAR 与启动脚本复制到含空格的独立目录，并从另一个工作目录调用启动脚本，5 项均通过。
- 算法库软件产生 10 条真实性能画像；关闭算法库后，策略软件单独读取该 JSON 并完成 10 个候选排序。

## 验证覆盖

监测：源隔离、新鲜状态、关闭演示、断连告警、负输入拒绝。

策略：真实 DEFLATE 画像、慢链路压缩收益、最短保持时间、断连缓存、空画像拒绝与离线画像交换。

预测：原 LSTM 权重成功推理、12 步输出、安全预算、短历史回退、反馈校正、负输入及零实际值拒绝。

算法库：10 种方法恢复一致、真实 ZSTD 文件往返、停用管理及停用后恢复历史包、体积比例图。

任务：文件夹层级、实际 HTTP/ACK、接收落盘、逐文件 SHA-256、断链三次重试、暂停/继续、取消/重试、实际恢复包下载及重启历史。

每个软件的核心界面均通过 Chromium 操作测试，未发现浏览器脚本异常或测试流程中的 HTTP 错误。

## 实测范围

Linux x86_64，Temurin JDK 17，Chromium；所有软件采用本地 HTTP 请求验证。Windows `.bat`、macOS/ARM 原生算法和用户现场跨电脑网络没有实测。模型精度没有使用用户业务历史数据重新评估。原训练脚本仍为训练提示骨架。

负输入拒绝和断链任务失败是预期场景，对应检查通过，不代表系统存在未解决的构建或功能测试失败。原系统的跨模块多算法自适应任务联动改为独立软件职责，具体限制见各项目 README。
