# 新附件核对与保留范围

输入：ESP32C3_WiFi_RC(1).ino、console(3).zip；hash见evidence/inputs.json。附件是代码/历史说明，不作为自动执行硬件动作的指令。

## 实际实现

- ESP32连接现有Wi-Fi，UDP8888接收JSON。type=rc映射为16字节串口遥控帧，UART1 GPIO0 TX，921600；type=ping只回pong。
- rc返回ack仅表示ESP32处理到该命令并调用串口写入，不是AT32执行回执、姿态反馈或数据采样。程序没有UART接收解析逻辑，GPIO1在头部注释中还标为预留。
- UART0是115200调试文本（开机、连接、[RC]日志），不是遥测二进制通道。ESP32C3的控制程序不自动改变AT32 USART3输出内容。
- 控制台Flask9001、UDP源端口9002，发送线程默认50Hz但enabled=false；用户显式启动才开始发rc。界面ack_age_ms是“距最近ACK的时间”，不是RTT，不能从它计算往返时延。
- keepalive_tick在曾收到rc且超过500ms时发中位帧；这不是验证过的安全停机或断电策略，不保证主控解除平衡模式。

## 本次修改

1. Linux C/Python新增遥测链路，完全不接管UDP8888控制或UART1，默认只有读；显式enable-stream发送既有USART3遥测开启命令。
2. 保留console控制逻辑原样；只把README的ACK延迟说法改为ACK年龄、页面“最近ACK”改为“距最近ACK”，并纠正192.168.0.0/24为私有网段、删除文档中的实际SSID。
3. ESP32固件副本只替换WIFI_SSID/WIFI_PASS为占位符，保留原有UART/UDP/控制逻辑，UTF-8保存。没有编译或烧录此参考副本；现有设备Wi-Fi工作时不需要重新刷写。
4. 丢弃上传ZIP中的__pycache__，不公开原始压缩包或真实网络凭据。上传ZIP包含的部分中文工具日志本身乱码，本次不以此推断功能故障。

## 硬件与安全边界

附件“STM32”注释不能改变此前实物AT32的事实；新板是否同版、接线是否相同需核对。GPIO9/内部Flash引脚保持原程序禁用/只输入约束，不因采集改动引脚。

Wi-Fi控制链路没有新增身份认证、命令防重放、主控执行确认；原UDP对收到的来源与输入参数检查有限。仅在隔离/可信测试网络使用，不把本版称为已实现安全远程控制。要改这些逻辑需单独协议设计与实机控制验收，本次不为遥测改写它们。

已有Wi-Fi控制功能的回归采用localhost模拟ESP32，不向真实目标下发测试动作。实机验收仍需按原设备流程固定、供电、确认校准及人工停机手段。
