# 整体操作步骤：从原有Wi-Fi控制到Linux遥测与分析

Windows主机+VirtualBox+Rocky用户请优先使用[专用完整步骤](Windows-VirtualBox-Rocky完整操作步骤.md)，其中包含DNF、Python版本、USB直通和SSH隧道；下面安装命令以Ubuntu为例。

## 1. 先确认三条串口的用途

| 链路 | 附件/既有工程配置 | 本次用途 |
|---|---|---|
| ESP32 UART1 GPIO0 TX → 主控控制输入 | 921600，附件注释称USART2 PA3 | 保留原无线遥控，不改、不接采集器 |
| ESP32 UART0 CN4 TX0/RX0 | 115200，调试打印 | 查看Wi-Fi连接日志，不当作AT32遥测 |
| AT32 Debug TXD/RXD/GND | 既有USART3遥测，230400/8N1 | USB-TTL → Linux采集 |

附件沿用“STM32”注释，但此前实物为AT32F403A。不能仅据注释断定新板型号、控制UART映射或ESP32 RX线路已接通；以你当前工作硬件、原理图及实测为准。本次不改这些引脚。

接线保持：USB-TTL RXD接AT32 Debug TXD；TXD接AT32 Debug RXD；GND共地。DIO、CLK、板端5V均不接USB-TTL。使用适配3.3V逻辑的转接器，板卡独立正常供电。停止XCOM和其他串口采集进程；不要接到ESP32下载口。

旧协议：0x23 + 16个小端float + sum8，共66字节，仅gyroXYZ、rcXY有意义。新raw26：RWT1 + 26float +序号/毫秒+CRC，共122字节，需AT32更新遥测固件。**不能从旧预留零推算电压或电流。**

## 2. 下载、目录与Linux选择

完整包为仓库deliverables/wheel-linux-v1.0.zip，校验对应SHA256SUMS文件。解压保留：

```text
wheel-linux/
reaction-wheel-compression-v1.1/   # 协议、例子、Java/Vue运行产物
aiot-platform/                    # 可选设备身份/弱网测试系统
```

建议Ubuntu22.04/24.04或兼容Linux。C采集器依赖Linux termios/poll，不能直接在Windows PowerShell运行。Linux实体机或有USB直通的虚拟机更适合首次实机；WSL2先做文件回放，USB-TTL需额外USB转发配置，Windows COM6不会自动成为/dev/ttyUSB0。Windows可继续运行原Wi-Fi控制台；遥测串口只分配给Linux一个系统。

安装：

```bash
sudo apt update
sudo apt install build-essential python3-venv python3-pip openjdk-17-jre nodejs npm
cd /你解压的位置/wheel-linux
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
make
java -version
node --version
```

Java17+、Node18.17+；发行版仓库版本可能不同，先检查，过旧时按官方说明安装匹配版本。Python3.10+。C文件/串口采集只需系统C工具，不依赖pyserial；Python上传只用标准库，numpy/matplotlib用于分析。不要用sudo pip全局安装。

## 3. 先做不接硬件的完整演示

```bash
python tools/demo.py --output runtime/demo-01
```

预期1000帧、100Hz、峰值10Hz。生成synthetic.rwt、原始input.uart、frames.dcw、samples.csv、collector.json、analysis/report.json、analysis/filtered.csv与analysis.png。所有输入明确是合成。输出目录拒绝覆盖。

先查看图、报告，再读src/collector.c的parse与output，理解字节流解析/校验/压缩/记录；读analyze.py的moving_average与频谱条件。程序可用不等于你已掌握Linux，建议按采集、解析、上传、分析四段逐个调试。

## 4. 启动压缩传输系统

在终端A的wheel-linux目录：

```bash
bash tools/start-compression.sh
```

脚本检查8080/8082未占用，启动包内Java JAR与Node桥接页面，默认均监听127.0.0.1，关闭自动辅助接收服务。日志位于runtime/services。打开 http://127.0.0.1:8080/wheel。Ctrl+C只停止该脚本启动的服务，不控制电机。

如果端口占用，先识别原进程，不要批量kill所有Java/Node。若从源码仓库运行而JAR/dist未构建，优先下载完整包；源码构建另见旧工程说明，不能使用不支持26通道的旧JAR冒充新版本。

终端B（同目录）：

```bash
source .venv/bin/activate
python capture.py --file ../reaction-wheel-compression-v1.1/examples/full-telemetry26.rwt --protocol raw26 --backend http://127.0.0.1:8082 --runtime runtime/replay-01
```

页面显示26通道，选择曲线分组；导出原系统32列CSV。回放结束应显示Pending durable batches: 0。页面只保留最近4000帧，长期原始记录和CSV保存在采集目录。

## 5. 保留原Wi-Fi遥控

Wi-Fi已可用就不重新烧录ESP32，不更改网络配置或控制程序。可以继续在原Windows机器运行console；若改在Linux运行，另开终端C：

```bash
cd /你解压的位置/wheel-linux/wifi-control/console
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
CUBLI_NO_BROWSER=1 python app.py
```

浏览器打开 http://127.0.0.1:9001；按你当前已验证的设备地址设置目标。默认不发送；确认设备固定与原控制流程后才手动启动。不把“启动发送”当成连接检查，也不照搬附件README中直接试自动平衡的步骤。

原ESP32固件参考副本已移除真实SSID/密码，需自行填写才能重刷。保留开发板包2.0.4与ArduinoJson6.x兼容性要求，但本环境未做Arduino完整编译/烧录。正常控制无需操作参考副本。

## 6. Linux确认USB-TTL与权限

插入转接器，执行：

```bash
ls -l /dev/serial/by-id/
ls -l /dev/ttyUSB* /dev/ttyACM* 2>/dev/null
id
```

设备名可能变化，优先使用/dev/serial/by-id/下稳定链接。若权限不足，在Ubuntu按实际设备所属组授权，例如：

```bash
sudo usermod -aG dialout "$USER"
```

退出登录后重新进入，再运行id核对。不要用chmod777或长期root运行解决。VM/WSL2先确认USB已交给Linux，Windows端关闭XCOM/串口监视器。

## 7. 接真实遥测

此前“屏幕4.4V、输出13V”的供电问题须先确认原因与电池规格，别依靠本程序判断电池能否继续运行。无线控制与电机停机仍按原设备流程。

确认旧固件时：

```bash
python capture.py --serial /dev/ttyUSB0 --protocol legacy --baud 230400 --enable-stream --backend http://127.0.0.1:8082 --runtime runtime/serial-01
```

确认已运行26通道RWT1固件时：

```bash
python capture.py --serial /dev/ttyUSB0 --protocol raw26 --baud 230400 --enable-stream --backend http://127.0.0.1:8082 --runtime runtime/serial26-01
```

enable-stream只发A0 AC 08 BA 66；默认不发送。采集器不发送CW1、摇杆、启停、平衡或断电命令。协议选择以实际帧为准，不根据Wi-Fi控制成功推断raw26已安装。

退出按Ctrl+C，查看输出目录：runtime/serial-01/serial-随机ID/。input.uart是原始串口字节；frames.dcw是压缩帧体；samples.csv是未滤波样本（legacy 为20列、raw26 为30列，含4列元数据）；与原系统CSV32列格式不同。NaN/Inf保留在原始DCW1，CSV文本标注，分析不会填零掩盖。

旧固件缺少电压、轮速、Id/Iq时，需基于当前实际控制工程合并旧工程提供的raw26五处遥测改动；不要整包覆盖现用Wi-Fi/控制工程。先完成Keil Rebuild、下载Verify、原校准区保护与控制时序验收；本次没有生成声称可直接烧录的新AT32固件。

## 8. 网络故障、缓存与恢复

不传backend时只采集本地，仍保留DCW1和CSV，同时生成待传队列。运行目录绑定target/backend/device，后续切换上传地址需用新runtime；已有离线DCW1可用旧系统wheel_agent --protocol dcw1 --replay导入新会话。

上传线程失败会指数退避，串口采集继续落盘；spool最多10000批，满时停止采集并保留已有记录，不静默覆盖。USB输入本身丢失、进程突然断电前未落盘部分不能自动恢复。原始记录可追查，磁盘容量需人工管理。

同一backend续传：

```bash
python capture.py --resume-only --backend http://127.0.0.1:8082 --runtime runtime/serial-01 --drain-seconds 60
```

不要同时用两个采集器打开同串口；同runtime有flock互斥，异常退出后锁自动释放。续传无需打开串口，不影响Wi-Fi控制。

Java幂等表仅内存保留最近256批、服务重启会丢失；本地持久化不意味着服务器永久exactly-once。Java会话切换清空页面历史，不宜多个网关同时向单个wheel端点写入。需要更强身份与持久化去重可用下一节已有AIoT接口。

## 9. 可选接入已有AIoT设备平台

运行同级aiot-platform/server.py，在8090页面注册设备，获取设备token。Linux终端用本地输入读取，不将token写进代码或Git：

```bash
read -rsp 'Device token: ' AIOT_DEVICE_TOKEN; echo
export AIOT_DEVICE_TOKEN
python capture.py --serial /dev/ttyUSB0 --protocol legacy --enable-stream --target aiot --device wheel-001 --backend http://127.0.0.1:8090 --runtime runtime/aiot-01
```

不要再开该平台原来的gateway争用串口。本采集器向AIoT平台上传数据，不发送它的网关心跳；其设备在线由上传更新，网关详细状态可能显示未知，不声称提供完整硬件健康认证。

## 10. 离线滤波与信号分析

采集结束后，将实际打印的目录代入，分析结果另建新目录：

```bash
python analyze.py runtime/serial26-01/serial-实际ID/samples.csv --channel gyro_x --window 5 --output runtime/analysis-01
```

raw26按设备序号/毫秒核对采样；有缺口、重启、重复或明显不均匀时关闭FFT，不插值伪造。uint32正常回绕按模运算处理。任意缺口不等同网络丢包，可能来自板端遥测跳槽或串口。

legacy没有设备采样率，默认不做FFT；仅当你有独立依据确定采样率时才显式提供，例如下式100Hz只是假设示例：

```bash
python analyze.py runtime/serial-01/serial-实际ID/samples.csv --channel gyro_x --window 5 --fs 100 --output runtime/analysis-assumed100
```

报告会标explicit_assumption。频谱使用去直流、Hann窗与rFFT，分辨率fs/N；至少32个有限、规则采样点才计算。最大峰不等于故障频率，静态或非平稳数据没有可解释的单一峰；混叠不能靠事后滤波消除。

滑动均值窗口W越大通常越平滑，也增大延迟；满窗名义群延迟(W−1)/(2fs)，预热与断点重置时不直接适用。NaN/Inf和序号断点会重置窗口。统计MAD离群只提供调查线索，不是训练好的故障分类器。不可将分析结果未经控制验证反馈到电机闭环。

## 11. 验证与排错

```bash
make test
make sanitize
python tools/check_java.py --backend http://127.0.0.1:8082 --output runtime/java-check-01
```

测试报告见evidence。ASan/UBSan用于内存/未定义行为检查，不代表硬件时序验收。

| 现象 | 检查 |
|---|---|
| Wi-Fi ACK增长但采集无帧 | ACK不是遥测；检查AT32 Debug接线/供电/230400/遥测开关 |
| 字节有、校验全错 | 是否接了ESP32调试口；legacy/raw26选错；波特率、电平或固件不匹配 |
| C程序提示permission denied | LinuxUSB权限/设备归属，VM/WSL直通与端口独占 |
| 上传pending增长 | 8082是否就绪，target/URL/令牌；看stderr和spool，采集无需等待网络 |
| 后端接收但页面无26字段 | 是否用完整包新JAR；AT32是否确实输出raw26 |
| FFT关闭 | 无采样率、有效点不足、序号缺口、不均匀或非有限值；先查原因 |
| Ctrl+C后轮子仍运行 | 停采不等于停机，使用原设备控制/物理流程 |

本地默认仅监听127.0.0.1。跨机器传输需受控网络与TLS/身份方案，不将无认证Java端口或控制Flask直接暴露公网。文件输出是用户数据，实测记录与Wi-Fi凭据不要提交到Git。
