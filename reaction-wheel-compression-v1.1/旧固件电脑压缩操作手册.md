# 旧固件动量轮 → 电脑压缩 → 压缩传输系统：完整操作手册

更新：2026-11-02。当前推荐方案保留动量轮旧固件，不需要 Keil 编译、烧录或 SWD 下载器。代码目录仍为 `reaction-wheel-compression-v1.1`，本次电脑压缩运行包版本为 v1.2。

## 1. 数据流与本次变化

```text
AT32 旧固件：传感器与电机控制保持原样
  → USART3：0x23 + 16个float32原始字节 + 求和校验（66字节）
  → 现有 USB-TTL / COM6，230400 / 8N1
  → 采集电脑 Python：校验、解析、ZRLE无损压缩，压不小时回退RAW
  → HTTP上传压缩二进制DCW1帧（最多20帧一批）
  → Java：CRC校验、无损解压、统计与最近数据缓存
  → /wheel：曲线、通道、电脑端配置、CSV导出
```

压缩发生在 Python 采集电脑，串口数据量不变。可以在同一台电脑验证，或将压缩帧发给另一台运行系统的电脑。没有把 Java 系统移植进 AT32，也不向旧固件下发 CW1 配置。

旧协议只有一个字节的求和校验，没有设备序号和采样时间；坏帧可重新同步但不能自动重传，求和相同的错误及偶然误同步不能全部检出。新增 CRC 保护的是电脑组帧后的传输，不能修复此前串口上未检出的错误。

## 2. 下载本次更新包

下载[电脑压缩完整运行包 v1.2](../deliverables/reaction-wheel-pc-legacy-v1.2.zip)，解压到新目录，例如 `D:\WheelCompress-PC`。旧目录先保留，以免覆盖已有采集记录。

找到包含 `start-legacy.ps1`、`firmware`、`DataCompress_System`、`serial-agent`、`examples` 的那层目录，即项目根目录。包中有本次构建的后端 JAR、前端 dist、网关依赖、采集器和示例；不用重建 Java/Vue。

不要使用旧 `reaction-wheel-compression-v1.1-integration.zip` 代替本次包：旧 JAR 不识别“电脑压缩旧协议”标记。直接获取 Git 源码时，按文末步骤重新构建后端和前端。

## 3. 接线与电脑环境

现有接法保持：USB-TTL GND→AT32 Debug GND，RXD→板端TXD，TXD→板端RXD。板端 DIO、CLK、电源脚继续留空，板卡按原方案供电；TX/RX 使用兼容的3.3 V信号。

端口以设备管理器当前结果为准；你最近的截图显示 CH340 为 COM6，不再沿用最初“CH340固定COM5”的假设。

安装 Java 17、Node.js 18.17+（使用依赖支持的版本）、Python 3.9+。在项目根目录打开 PowerShell：

```powershell
java -version
node --version
python --version
python -m pip install -r .\serial-agent\requirements.txt
python -m serial.tools.list_ports -v
Test-Path .\serial-agent\wheel_agent.py
Test-Path .\DataCompress_System\backend\target\data-compress-control-system-v5-5.0.0.jar
Test-Path .\DataCompress_System\frontend\dist\index.html
```

三个路径应返回 True。此前在 `C:\WINDOWS\system32` 执行的相对路径会找不到文件，必须先切到解压目录。后端运行只需 Java，修改/编译后端才需要 JDK/Maven。

## 4. 启动新版本上位机

先停止旧采集、结束 XCOM，并保存旧网页需要的数据。停止旧运行脚本；确认旧后端/网关已退出，再从新目录启动，避免复用旧 JAR。不要直接关闭其他不相关的 Java 服务。

窗口 A，在项目根目录执行并保留窗口：

```powershell
powershell -ExecutionPolicy Bypass -File .\DataCompress_System\run.ps1
```

出现 `System ready: http://localhost:8080` 后访问：

```text
http://localhost:8080/wheel
```

窗口 B 检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8082/api/wheel/status
```

新接口包含 `compressionLocation`、`timeSource`、`transportSavingPercent`。没有数据时来源为 UNKNOWN，显示等待设备正常。网页端口8080，代理上传后端端口8082。

## 5. 可先回放验证电脑压缩

窗口 B，在根目录执行：

```powershell
python .\serial-agent\wheel_agent.py --protocol legacy --replay .\examples\legacy-gyro.uart --backend http://127.0.0.1:8082 --pace 0.2
```

预期：1000帧完成、网页显示历史回放，出现角速度曲线，压缩位置为电脑。回放不打开串口，不向设备发命令，不确认实时配置。

示例由既有历史CSV生成，含大量预留零；用于软件链路验证，不是当前动量轮实机测试，也不能代表全部通道启用后的压缩率。回放结束约3秒后变为等待设备。回放与实机不要同时向同一后端上传。

## 6. 实机采集：COM6

关闭 XCOM 的串口，确认动量轮运行旧固件并正常供电。窗口 B 执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\start-legacy.ps1 -Port COM6
```

也可双击根目录 `start-legacy.bat`，默认 COM6；脚本会检查/安装 pyserial，并启动下面的等效命令：

```powershell
python .\serial-agent\wheel_agent.py --protocol legacy --port COM6 --baud 230400 --enable-stream --backend http://127.0.0.1:8082
```

端口不同，只改 COM6。`--protocol legacy` 必须明确指定：为兼容此前板端方案，直接调用 wheel_agent.py 的默认协议仍是 dcw1。

代理只在启动时发送一次 `A0 AC 08 BA 66` 开启遥测，不发送电机校准/转动/停机命令。配置模式下不向旧固件发送CW1。板卡重新上电后如没有输出，重启代理再次开启遥测。

成功判据：

1. 终端出现串口、记录文件路径及“电脑压缩旧协议”。
2. 约每5秒日志的串口累计字节、有效接收、上传数量持续增加。
3. 网页显示“正在接收”、旧固件→电脑压缩，最新数据不断变化。
4. 配置选择 AUTO/RAW 后能出现“采集电脑已确认配置”。

若接收增长但上传不增长，查8082与HTTP日志；若原始记录增长但有效接收为零，查协议、230400、求和校验。记录文件的 `.legacy` 是原始二进制，不是 XCOM 文本导出。

## 7. 页面配置的准确含义

- AUTO：电脑逐帧尝试ZRLE，编码载荷小于64字节才使用压缩；否则RAW。
- RAW：电脑封装原始64字节载荷，仍带DCW1头和CRC，并非直接上传旧66字节帧。
- 上传组批周期：10～1000 ms整数，控制电脑端组批等待时间目标；最多20帧一批，满批可提前上传，线程调度和网络会造成额外延迟。
- 周期不会丢弃有效样本，也不会改变板端采样周期、USART波特率、FOC或电机控制。
- 代理约每2秒获取配置；后端依据后续帧回传的电脑配置确认。保存成功与应用确认是两件事。

配置在后端/采集器内存中，不写AT32 Flash。建议先AUTO/100 ms验证，再按需要降低组批周期。

## 8. 旧协议通道与时间

| 通道 | 当前仓库旧固件输出 |
|---|---|
| 1～3 | gyro_x/y/z，原工程滤波角速度，°/s |
| 4～14 | 预留，原 Debug.c 填零；不是已测得的姿态、轮速、电流或电压 |
| 15～16 | rc_x/y，原遥控输入单位 |

全部64字节原始位模式都保留，不做float重编码或有损量化。网页将4～14通道标为“未提供（预留）”，CSV用reserved_04～reserved_14列名保留原值。若你的旧固件改过通道布局，应先核对它的Debug.c再解释通道。

旧协议没有设备时间和序号，因此：

- 序号是电脑识别有效帧后生成的编号，不能据此证明串口无丢帧。
- 时间是本次代理启动以来的电脑接收/处理经过时间，不是硬件采样时间；一次读取的多帧可能具有相同毫秒值。
- API为兼容沿用`deviceMillis`字段，但`timeSource=HOST_RECEIPT`；CSV改为host_sequence、host_elapsed_ms。
- 回放时间重新生成，不能恢复原始采样节奏，也不能可靠识别板端重启。

## 9. 比较压缩收益

页面统计从后端启动开始累计，含历史回放。切换模式后不能用混合累计值当新阶段结果，需按起止计数差比较。

- 载荷节省：编码载荷相对每帧64字节。
- 同协议整帧节省：DCW1总字节相对每帧86字节RAW。
- 网络帧体相对输入帧节省：本方案DCW1总字节相对校验有效的旧66字节帧。可能为负；不含HTTP/TCP头，也不是串口节省。

ZRLE在全零等数据上有效，高熵数据回退RAW。电脑RAW封装86字节，相对旧66字节会增加30.3%的帧体字节。不能把载荷节省直接当成实际网络带宽节省，实际网络收益还受批量与协议开销影响。

## 10. 记录、导出与恢复

默认保存到当前工作目录的 `runtime\wheel-UTC时间.legacy`。可指定实验文件：

```powershell
python .\serial-agent\wheel_agent.py --protocol legacy --port COM6 --baud 230400 --enable-stream --backend http://127.0.0.1:8082 --record .\runtime\test01.legacy
```

文件已存在会拒绝覆盖，换新文件名。原始记录包括坏候选及命令回显，回放重新解析有效帧。

网页CSV只导出当前会话最近最多4000帧；切换会话会清空当前历史，服务重启内存数据丢失，先导出重要数据。

断网时继续串口记录，网络重试。待传队列最多100批，满后未上传丢弃计数增加，内存队列不保证退出后保留；本地原始记录可供恢复。先停止实时采集，再执行：

```powershell
python .\serial-agent\wheel_agent.py --protocol legacy --replay .\runtime\test01.legacy --backend http://127.0.0.1:8082 --pace 0.2
```

回放上传整份文件并创建新会话，不是按帧断点续传，已上传内容可能再次计数；无法恢复串口上未收到的字节。

停止：先导出CSV，在代理终端Ctrl+C，再按原板流程停机，最后关闭系统。Ctrl+C与关闭网页都不是电机停机命令。

## 11. 两台电脑

A接动量轮和USB-TTL，B运行新系统，例B的IP为192.168.1.20。允许A访问B的8082，查看网页还需要8080。

A执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\start-legacy.ps1 -Port COM6 -Backend http://192.168.1.20:8082
```

B打开`http://localhost:8080/wheel`，A可访问`http://192.168.1.20:8080/wheel`。压缩在A，解压在B；不需要第二个USB-TTL。当前后端只接一个动量轮数据源。本例面向受控局域网，公网部署另需认证和加密设计。
