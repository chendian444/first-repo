# 数据压缩控制传输系统

这是一个完整的独立系统，包含后端服务、前端页面、系统网关和可选远端接收服务。

## 系统结构

```text
浏览器 http://localhost:8080
        │
        ├─ 前端静态资源（frontend/dist）
        │
        └─ /api
             ├─ 仪表盘接口      → 系统网关字段适配
             ├─ 本地文件选择/暂存 → runtime/uploads
             └─ 任务、网络、告警接口 → 后端服务
                                      │
                                      ▼
                              后端服务 http://localhost:8082
```

点击“选择文件”后，浏览器会把文件上传到系统网关暂存；点击“开始发送”后，系统网关再把该文件提交给后端服务执行真实识别、压缩、传输、恢复和完整性校验。

传输任务队列保留文件或文件夹的原始名称。文件任务可直接“打开文件”；所有任务均可通过“打开文件夹”查看其在任务包中的位置、任务状态和文件列表。采用 NONE（不压缩）策略时，效果页会按直传场景说明封装、恢复与校验开销，不再显示虚假的压缩收益。

策略页的“预测与实际曲线”接入后端服务的 `/api/network/forecast`，使用内置 `COMPACT_PRETRAINED_LSTM` 模型；历史样本不足时会自动使用回退预测器。图表 Y 轴会按当前预测值和实际值动态缩放，不再固定到过大的范围。

## IDEA 使用

用 IDEA 打开 `C` 文件夹，在 IDEA 的 Terminal 中执行：

```powershell
.\run.ps1
```

启动完成后访问：

```text
http://localhost:8080
```

如果要分别调试后端服务和系统网关：

```powershell
cd backend
mvn spring-boot:run "-Dspring-boot.run.arguments=--server.port=8082"
```

另开一个 Terminal：

```powershell
cd bridge
npm start
```

需要前端热更新时，到 `frontend` 执行：

```powershell
npm install
npm run dev
```

然后访问 `http://localhost:5173`。

## bat 是什么

`.bat` 是 Windows 批处理启动器。双击 `run.bat` 时，它只是调用同目录的 `run.ps1`，真正的启动逻辑在 PowerShell 脚本里。

当前不是打成一个 exe，而是已经预构建好了两个运行产物：

- `backend/target/*.jar`：后端服务可运行 JAR。
- `frontend/dist`：前端页面打包后的静态资源。

`run.ps1` 会先用 Java 在 8082 启动后端服务，再用 Node 在 8080 启动系统网关。系统网关负责提供前端页面，并处理或转发 `/api` 请求。

如果构建产物不存在，脚本才会尝试调用 Maven 或 npm 重新构建。

## 一键启动

双击：

```text
run.bat
```

或执行：

```powershell
.\run.ps1
```

## 另一台电脑访问和接收

同一局域网内，其他电脑可以访问发送端电脑的地址，例如：

```text
http://发送端电脑IP:8080
```

这样访问的是同一个系统页面，可以查看任务状态、预测曲线、压缩结果，并下载恢复包。

如果要让另一台电脑自动作为接收端落盘文件，需要在接收端电脑也启动接收服务：

```powershell
.\run-receiver.ps1
```

默认监听 `8081`，收到的文件保存在：

```text
runtime\received
```

发送端电脑启动前配置接收端地址：

```powershell
$env:RECEIVER_URL = 'http://接收端电脑IP:8081'
.\run.ps1
```

然后两台电脑都可以继续访问发送端的同一个页面。任务完成后，发送端会把恢复包自动投递到接收端电脑。

## 行为边界

当前系统的跨电脑接收方式是在任务完成并生成恢复包后，将恢复包投递到接收端电脑保存；任务内部的压缩、恢复和校验仍由后端服务完成。

暂停任务不会伪造状态；如果当前服务不支持暂停，页面会提示任务继续执行。重置只清除当前视图，不删除历史任务。

## 网络实际曲线说明

系统默认开启动态网络采样模式。没有外部遥测接入时，页面里的实际网络曲线会使用系统内置的动态采样值，避免长期固定在 1.2 Mbps；如果接入真实遥测，外部遥测会自动覆盖内置采样。

## 接收端完整同步修复

当前版本已支持发送端将任务队列、实时进度和任务完成后的压缩前后时间对比一起推送到独立接收端。接收端直接运行 `run-receiver.bat` 并打开 `http://localhost:8081/receiver` 即可，不需要配置发送端 Java 后端地址。详见 `RECEIVER_DASHBOARD_SYNC_FIX.md`。
