# 多模态监测数据动态压缩与传输控制系统 V5

本项目根据多源接入、多模态识别、数据分级、网络感知、动态压缩、接收恢复和异常告警七类功能重新设计。它是一个可直接在 VS Code 中运行的 Spring Boot JavaWeb 工程。

## V5 的性能修正

旧版在每次传输请求中训练深度学习模型，导致预测等待时间很长。V5 改成：

```text
离线训练 Compact LSTM
        ↓
模型权重随系统打包
        ↓
系统启动时加载一次
        ↓
每次预测只做纯 Java 前向推理
        ↓
实际速率反馈修正安全传输速率
```

运行时没有 DL4J、ND4J，也不会重新训练模型。模型推理通常只需要毫秒级时间。离线训练脚本位于：

```text
training/train_rate_model.py
```

## 功能对应

### 1. 多源数据接入

- 数据源注册与状态展示
- 内置传感器、摄像头和日志系统示例
- 记录设备编号、接口地址、业务场景、累计数据量和最近上报时间
- 文件上传统一封装为传输任务

### 2. 多模态识别

综合使用：

- 扩展名
- MIME 类型
- 文件头魔数
- 数据源类型
- 业务场景
- 文件前部样本
- 文本结构和分隔符特征

输出数据模态、格式、已压缩判断、可压缩性、预处理建议、候选算法、级别范围、置信度和策略标签。

### 3. 数据分级管理

支持：

```text
CRITICAL  关键数据
IMPORTANT 重要数据
NORMAL    普通数据
```

任务进入 `PriorityBlockingQueue`。关键数据优先发送；普通数据允许缓存、延迟和批量；断连时保留任务偏移。

### 4. 网络状态感知

每 500 ms 记录：

- 有效吞吐率
- RTT
- 抖动
- 丢包率
- 重传次数
- 连接状态
- 网络质量
- 队列与缓存
- CPU 和内存

系统默认启用网络波动模拟，便于演示。真实边缘节点可调用：

```http
POST /api/network/telemetry
```

上传实际测量值。关闭模拟后，页面中的“实际速率”来自该遥测接口。

### 5. 动态压缩与传输组织

自动模式根据以下因素选择策略：

```text
数据模态
数据等级
已压缩判断
当前网络质量
LSTM 预测速率
预测反馈修正后的安全速率
压缩画像
排队代价
丢包重传代价
策略切换收益
```

实时候选集经过裁剪，避免测试所有高级别算法造成卡顿。系统只使用 64 KB 代表性样本建立压缩画像，随后只对最终选中的策略执行完整分块压缩。

支持：

```text
NONE
GZIP
DEFLATE
ZIP
BZIP2
LZMA
LZ4
ZSTD
SNAPPY
BROTLI
```

关键数据只参与快速候选；普通数据可使用更高压缩级别。

### 6. 接收恢复与完整性校验

每个分块记录：

- 任务编号
- 分块序号
- 文件偏移
- 算法与级别
- 原始大小和压缩大小
- 重传次数
- SHA-256 校验结果

接收端执行解压恢复和字节一致性校验。校验失败自动进入补传，超过最大次数产生告警。

### 7. 告警与异常处理

当前实现覆盖：

- 低带宽与拥塞
- 高丢包
- 网络断连
- 传输失败
- 重试耗尽
- 完整性失败
- 队列和资源异常接口

页面支持筛选和确认处理告警。

## 页面

### 传输监控

按照“发送端—链路—接收端”布局展示：

- 发送参数
- 自动识别结果
- 任务进度
- 接收恢复状态
- 关键指标
- 网络实时曲线
- 优先级任务队列

### 策略分析

展示：

- 实际网络速率曲线
- LSTM 预测速率曲线
- 安全传输速率曲线
- t1、t2 等策略调整点
- 当前推荐策略
- 预测误差和反馈系数
- 策略调整原因
- 分块执行明细

### 效果展示

对比：

- 不压缩估算传输耗时
- 实际压缩耗时
- 网络传输耗时
- 解压耗时
- 优化后总耗时
- 节约时间与效率变化
- 完整性结果和网络总体状态

另包含数据源管理和告警中心。

## 环境要求

- JDK 17 或以上
- Maven 3.6.3 或以上
- VS Code Extension Pack for Java

## 启动

```powershell
mvn -U clean spring-boot:run
```

Windows 也可运行：

```text
run.bat
```

浏览器打开：

```text
http://localhost:8080
```

## 国内 Maven 网络

如中央仓库访问不稳定，将 `settings-example.xml` 复制为：

```text
C:\Users\你的用户名\.m2\settings.xml
```

然后清理 `.lastUpdated` 文件并执行：

```powershell
mvn -U clean package
```

## 演示建议

1. 打开系统后保持默认网络模拟。
2. 选择“产线传感器”。
3. 上传 `sample-data/monitoring-data.csv`。
4. 数据等级选择“自动分级”。
5. 控制模式选择“自动动态控制”。
6. 创建任务后切换到“策略分析”。
7. 查看实际速率、预测速率和安全速率曲线。
8. 观察 t1、t2 等策略切换点及调整原因。
9. 任务完成后查看“效果展示”。

## 真实性说明

- 压缩、解压、分块恢复和 SHA-256 校验为真实执行。
- 默认网络速率来自可控模拟器，目的是复现波动、拥塞和短时断连。
- 接入 `/api/network/telemetry` 后，实际曲线可使用边缘节点测得的真实吞吐率、RTT、抖动和丢包。
- 网络传输耗时由实际遥测速率和压缩后字节数计算；如需物理链路的真实字节发送，应把同一策略引擎接入 Netty/WebSocket 分块通道。
- CSV 列式整理、空值位图和字典编码当前作为策略建议和扩展接口保留，默认传输链路保证原始字节无损。

### 本次维护更新

- 图表只在当前可见页面绘制，避免页面切换后 canvas 按隐藏布局反复重算导致自动放大。
- 网络状态快照与策略曲线的纵坐标会按数据波动自动保留小数，避免 1199/1200 等重复刻度。
- 横坐标改为采样点编号，并在刻度下方标注对应累计耗时，便于按采样点追踪网络状态。
- 完成的压缩任务会写入 `app.history.dir` 指定目录，其他客户端打开同一服务即可看到并下载历史压缩包/恢复包。
