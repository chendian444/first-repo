## 结论：只替换两个文件

先解压原ZIP。设解压根目录为：

```text
C:\Users\bmdijhroe\Downloads\wheel-linux-raw26-new\
```

替换以下两个文件（补丁包已带完全相同的目录层级）：

```text

reaction-wheel-compression-v1.1\firmware\UserFile\WheelTelemetry.h
```

## Keil编译、下载及现场验收

1. 打开新目录reaction-wheel-compression-v1.1\firmware\USER\AT32F403A.uvprojx；确认实际器件AT32F403ARCT7、C99、ARM Compiler5及原FOC库。芯片/板卡若不同，以实际工程为准。
2. 在Keil里打开UserFile/WheelTelemetry.c，确认有float samples[26]与RWT1；Rebuild，检查0 Error(s)、RAM/Flash与警告。不以已有旧AXF或历史日志当成功。
3. 下载前保留原固件与校准资料，核对擦除范围，勿为连接随意全片擦除。用已经确认兼容的AT32下载方式执行Download及Verify；Rebuild不会自动更新芯片。
4. 未解决的MDK产品/许可证错误（C9511E/C9555E）仍需修复本机授权环境，不能靠这两个C文件消除。不能用STM32CubeProgrammer烧AT32。
5. 新模块只扩展采样输出；变量读取并非同步快照。100Hz、122字节帧8N1预算占230400约53%，不是实测CPU占用。控制时序、物理量标定和实机稳定性仍需验收。

采集器已把原始帧压缩后上传DCW1来源标记2。页面应出现26个字段，不再显示reserved_04~14；设备时间来自板端。仅修改采集参数而不烧录AT32，会导致解析不到有效帧。

## 26字段顺序

| 序号 | 字段 | 板端来源 |
|---|---|---|
| 1–3 | gyro_x/y/z | mpu6500.gyro.filter.x/y/z |
| 4–5 | angle_x/y | mpu6500.gyroAngle.x/y |
| 6–8 | wheel1/2/3_speed | M1/2/3_Encoder.Speed_filter |
| 9–11 | encoder1/2/3_raw | M1/2/3_Foc.Encoder_data |
| 12–14 | wheel1/2/3_id | M1/2/3_Foc.Id |
| 15–17 | wheel1/2/3_iq | M1/2/3_Foc.Iq |
| 18–19 | battery_v / battery_filtered_v | Cubli.BatVin / BatVin_filter |
| 20–22 | rc_x/y/z | Rc.x_f/y_f/z_f |
| 23–26 | protect_flag / auto_mode / manual_mode / calibrated | Cubli对应状态 |

这些是已有变量，不生成虚构姿态Z。编码器是计数；速度原公式对应度/秒；Id/Iq物理单位要现场核对。静止或未进入某状态时为0可能正常，26通道不等于26条必须持续非零的数据。
