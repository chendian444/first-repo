# 动量轮数据压缩传输控制完整操作手册

更新：2026-10-29。适用于本仓库 `reaction-wheel-compression-v1.1`，以 Windows PowerShell 为例。

本文按已确认的硬件重排：**CH340 → COM5；STC 是支持普通收发的 USB-TTL → COM6；AT32 已以 QFP/LQFP 封装焊在动量轮 PCB 上**。通过 PCB 接口、测试点或焊盘连接即可，不需要拆卸芯片、打开封装或接触硅片。

仓库提供集成固件源码及上位机软件。既有协议、模拟串口和页面测试见[验证报告](验证报告.md)；真实 AT32 的完整 Keil 编译、烧录和控制时序验收尚未完成，包内没有已通过实机验收的新固件 BIN。本手册给出操作步骤与验收标准，硬件效果仍需在实物上验证。

## 1. 先明确链路与设备分工

```text
动量轮 IMU / 编码器 / FOC 等变量（16 个 float32，共 64 字节）
  → 板载 AT32：RAW 或 AUTO（有收益时使用 ZRLE 无损压缩）
  → USART3 DMA：DCW1 帧 + 序号 + 设备时间 + CRC16
  → 一个 USB-TTL：CH340/COM5 或 STC/COM6
  → Python：解析筛选、原始字节记录、上传压缩帧
  → HTTP：同机或另一台电脑
  → Java：再次校验、解压、统计和缓存
  → 网页 /wheel：显示曲线与统计，导出 CSV

配置下行：网页 → Java → Python → USART3 → AT32
配置确认：AT32 在后续 DCW1 遥测帧中回传实际模式与周期
固件更新：电脑 → 支持该 AT32 的 SWD 下载器 → PCB 的 SWD 接口
```

| 设备/功能 | 用途 | 本次选择 |
|---|---|---|
| CH340，COM5 | TTL 串口采集和下发遥测配置 | 优先用它走通流程 |
| STC，COM6 | 同上，按你确认的普通 USB-TTL 使用 | 可替换 CH340；仍要确认 3.3 V 信号、230400 支持 |
| SWD 下载器 | 将新固件写入 AT32 Flash | 用 AT-Link、J-Link 等明确支持该器件和所用软件的工具；其他探针需核实兼容 |
| 网页压缩配置 | 设置 RAW/AUTO 和遥测周期 | 不设置轮速、转矩、PID 或 FOC 参数 |
| 原板电机控制 | 原传感器、FOC、平衡和保护 | 沿用原板卡操作与验收流程 |

**正常采集只需要一个 USB-TTL，不需要把 COM5、COM6 串联。** COM 号由 Windows 分配，不是 AT32 内部 USART 编号；重插或换 USB 口后重新核对。

USB-TTL 本身没有 SWD 能力。UART ISP 只有在核对准确 AT32 型号、官方 Boot ROM 支持的串口引脚、启动模式和下载软件后才可采用；不能由“STC 可以收发”推出“STC 下载软件能烧 AT32”，也不能由应用使用 USART3 推出 Boot ROM 支持该接口。本手册采用 SWD 路线。

## 2. 确认 PCB 上的接线位置

### 2.1 仓库原理图已引出 CN3 Debug

查看[原理图](firmware/SCH_Cubli_Mcu_V1.5_2024-02-16.pdf)第 1 页，`CN3 Debug` 同时引出了串口和 SWD：

| CN3 电气脚号 | 图中网络/路径 | 用途 |
|---:|---|---|
| 1 | DGND | 信号地 |
| 2 | 经 D1 连接 5.8 V 电源网络的路径 | 电源相关脚；不能当作 3.3 V VTref，本流程不接 USB-TTL 电源线 |
| 3 | SW_CLK，经 R6（33 Ω） | SWD 时钟，MCU PA14 |
| 4 | SW_DIO，经 R5（33 Ω） | SWD 数据，MCU PA13 |
| 5 | USART3_TX，经 R4（33 Ω） | 板端发送，MCU PB10 |
| 6 | USART3_RX，经 R2（33 Ω） | 板端接收，MCU PB11 |

图中 CN3 型号为 `SM06B-GHS-TB(LF)(SN)`，还有固定焊脚，不能把固定焊脚当成六根信号之一。旁边 CN4 与 ESP 串口有关，不能仅凭“都是串口插座”替代 CN3。

**这是仓库图纸的电气脚号，不是“从你眼前左边数”的说明。** 必须核对实物 PCB 版本、1 脚标记、插座观察面及线束定义。插头正面和背面观察的左右顺序可能相反；实物版本不同则按对应版本图纸操作。

### 2.2 没有丝印或没有焊插座时

1. 断开板卡全部电源和 USB，先查 PCB 丝印、板卡说明及接插件 1 脚标记。
2. 用万用表通断/电阻档核对地及信号网络；CN3 与 MCU 间有 33 Ω 电阻，不能只凭蜂鸣器是否响判断。
3. 优先用配套线束、测试点或已确认的焊盘引线；焊接在断电下进行，检查焊桥与固定。
4. 未确认脚序时，先完成后面的软件回放，不猜线。

PB10/PB11 是 MCU GPIO 名称，不是 CN3 第 10/11 脚。仓库图纸中 AT32F403ARCT7 的 PB10/PB11 对应封装 29/30 脚，仅用于核对网络；日常连接优先走 CN3，不把杜邦线夹在密集芯片引脚上。

## 3. 准备物品、驱动与适配器测试

需要：动量轮及符合原规格的供电、一个 3.3 V 信号电平 USB-TTL、信号线。更新固件另需兼容该 AT32 的 SWD 下载器。电脑安装 Java 17、Node.js 18.17+、Python 3.9+；固件编译需要 Keil µVision、完整注册且有效授权的 ARMCC 5.06 和 `ArteryTek.AT32F403A_407_DFP` 设备包。

### 3.1 驱动下载后还要检查安装

1. 安装已下载的 CH340 驱动，按提示重插设备。
2. 设备管理器 → “端口（COM 和 LPT）”：CH340 为 COM5、STC 为 COM6，均无黄色感叹号。
3. 分别拔插确认对应关系；端口号变化时以当前显示为准。
4. STC 适配器的驱动按实际 USB 桥接芯片安装，不根据外壳名称推断芯片型号。

能枚举 COM 口只证明设备识别成功，还需要确认实际收发和电平。

### 3.2 回环自检

让适配器与动量轮完全断开，只短接适配器自己的 TXD 与 RXD，不接 VCC。串口助手选择 COM5 或 COM6、230400、8N1、无流控，关闭本地回显，发送文本，应收到同样内容。测试后关闭助手并拆除短接线。

分别测试两个适配器可排除电脑侧问题。回环不能证明 TX 为 3.3 V、板端接线正确或固件正确；应查模块说明或测量实际 TX 高电平。部分模块的 3.3 V/5 V 跳帽只切换供电脚，不切换信号电平。

也可在两个适配器都与动量轮断开的情况下交叉测试：COM5 TX→COM6 RX、COM6 TX→COM5 RX、GND↔GND，两侧 VCC 都不接，在两个串口窗口双向发收。它仍不是动量轮压缩链路。

## 5. 不接硬件，先完成上位机回放

在项目根目录的 PowerShell 窗口 A 执行并保持运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\DataCompress_System\run.ps1
```

打开 `http://localhost:8080/wheel`。网页/网关使用 8080，Java 后端使用 8082，采集程序的 `--backend` 指向 8082。

另开项目根目录终端检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8082/api/wheel/status
```

应返回 JSON；未接入时“等待设备”正常。404 时核对 JAR 是否含动量轮接口，并确认没有旧服务占用 8082。脚本可能停止旧的空闲服务或复用已有服务，需保留的数据应先导出；后端内存数据会受重启影响。

窗口 B 回放：

```powershell
python .\serial-agent\wheel_agent.py --replay .\examples\historical-gyro.dcw --backend http://127.0.0.1:8082 --pace 0.2
```

通过条件：终端显示“历史回放完成: 1000 帧”，网页显示“历史回放”、有效帧增加并出现角速度曲线，可导出 CSV。结束约 3 秒后回到等待设备。回放不打开 COM5/COM6。

该示例来自旧 CSV，角速度和末尾遥控通道保留原始意义，中间有大量预留零，设备时间按测试生成。它证明上位机传输/解压链路，不证明实机已接入，也不能代表新 16 通道压缩率。启动实机采集前结束回放；一个后端避免多个代理同时上传。

## 6. 编译新 AT32 固件

USB 驱动或上位机安装不会更新板端程序。原 `0x23 + 16 float + sum` 帧不能直接当作新 DCW1 使用。

1. 打开 `firmware\USER\AT32F403A.uvprojx`，核对目标 `AT32F403ARCT7` 与实物一致；不同型号先核对适配与存储布局。
2. 安装设备包，选择 ARMCC 5.06。原工程为 update 6，使用 update 7 需本机产品与授权支持。
3. 核对工程已包含 `WheelCodec.c`、`WheelTelemetry.c` 及原 `AT32F403A_FOC_LIB.lib`；v1.1 已显式定义芯片宏并启用 C99。
4. 可先在项目根目录执行静态预检查：

```powershell
python .\tools\check_keil_build.py
```

可选：用本机实际 ARMCC5 Bin 路径检查最小 C 编译/链接：

```powershell
python .\tools\check_keil_build.py --arm-bin 'D:\Keil\ARM\ARM_Compiler_5.06u7\Bin'
```

静态通过只证明 XML、路径和设置；最小探针也不覆盖启动汇编及 FOC 链接。必须在 µVision **Rebuild**，确认最终 `0 Error(s)`、处理警告并检查 Flash/RAM 和链接结果。

若为 `C9511E/A9511E`、`Product: unknown`、`product not found`，按[Keil 构建修订说明](Keil构建修订说明.md)检查 License Management、完整安装和注册。此前这类日志在源码检查前已失败，换串口或装 CH340 驱动不能修复；也不能保证授权恢复后没有其他编译错误。不要未经验证仅为绕过环境问题切换 Compiler 6。

当前工程默认输出 `firmware\USER\Objects\AT32F403A.axf`，未启用自动 HEX，也不默认生成 BIN。配置正确时可直接通过 Keil 下载新 AXF。不要拿旧 BIN/AXF 的存在作为这次构建成功的依据；记录本次构建日志、文件时间和版本。

## 7. 通过 SWD 烧录焊在板上的芯片

### 7.1 下载前

记录板卡型号、原固件版本和校准状态，按原板说明备份需要保留的程序/校准信息。原工程从 Flash 读取校准数据，下载工具擦除范围可能影响它们，需核对存储与恢复流程，不把全片擦除、解除保护或改选项字节当作默认连接排错。

固定动量轮，按原板方案使执行机构处于可控状态。新程序上电仍执行原初始化和控制逻辑，“只接遥测”不代表电机绝不会运动。

### 7.2 SWD 接线

断电接线，然后按原方案给板卡供电。以下编号仅用于已核对版本一致的 CN3：

| 下载器端 | 板端 |
|---|---|
| SWDIO | CN3-4，SW_DIO / PA13 |
| SWCLK | CN3-3，SW_CLK / PA14 |
| GND | CN3-1，DGND |
| VTref/目标电压检测输入（若探针需要） | 板上确认的 AT32 3.3 V 电源测试点；CN3 未提供可直接视为 3.3 V VTref 的脚 |
| nRESET（按工具/板卡需要） | 已确认的 NRST 测试点，CN3 未单独引出 |

**CN3-2 接电源路径，不能当 3.3 V 参考。** VTref 通常是检测输入，不与探针供电输出混用；以实际探针说明为准。USB-TTL 的 VCC 不给动量轮或电机供电。

SWDIO/SWCLK 与 PB10/PB11 串口不是同一接口。SWD 下载器不一定显示成 COM 口，应在下载软件内检查识别。

### 7.3 Keil 下载与复位

1. `Options for Target → Debug` 选择实际探针驱动，在 Settings 选 SWD，首次可用 100～1000 kHz 等较低速度连接。
2. 核对目标电压和芯片识别。仅出现 ARM SW-DP ID 不等于核对了完整器件型号。
3. 在 Utilities / Flash Download 核对驱动、Flash 算法与实物。当前 RCT7 工程指定 `AT32F403A_256.FLM`、起始 `0x08000000`、容量 `0x40000`（256 KiB）。
4. 历史 `.uvoptx` 含其他探针/器件配置字符串，不能把其中 1 MiB 算法直接当作当前 RCT7 的正确设置；按当前目标、实物和设备包核对。
5. 使用完整 Rebuild 成功的新产物执行 Download，确认写入与 Verify 成功，保存日志。
6. 退出调试、复位或重新上电，使程序脱离断点正常运行，再检查 DCW1 实际输出。

连接失败先检查供电、地、脚序、VTref、探针支持、速度与驱动；需要复位下连接时先确认 NRST 接点。如果板端已烧入正确新固件并能输出有效 DCW1，无需每次重烧。

## 8. USB-TTL 接线：CH340 与 STC 二选一

先断电核对线序。板卡独立按原硬件方案供电，只连接三个信号：

| USB-TTL 端 | 板端信号 | 同版本 CN3 |
|---|---|---:|
| RXD | PB10 / USART3_TX，板向电脑发送 | 5 |
| TXD | PB11 / USART3_RX，电脑向板发送 | 6 |
| GND | DGND | 1 |
| VCC / 5V / 3V3 | 本流程不连接 | 不接 2 |

```text
CH340(COM5) 或 STC(COM6)        动量轮 PCB
RXD  ←──────────────────────  CN3-5 / USART3_TX
TXD  ──────────────────────→  CN3-6 / USART3_RX
GND  ───────────────────────  CN3-1 / DGND
VCC  不连接                   板卡沿用原供电
```

参数：**230400 bit/s、8 数据位、无校验、1 停止位、无流控（8N1），3.3 V TTL 信号**，不是 RS-232/RS-485。先用短线验证，长距离另行设计物理层。

不要让两个适配器 TX 同时驱动 PB11。换适配器先停止采集、断电换线，再按新端口启动。串口助手、旧调试脚本和采集器不能同时占用同一 COM。

## 9. 实时接入：直接使用你的 COM 号

保持上位机服务运行，结束回放并关闭串口助手，确认板端新固件运行且已供电。在项目根目录执行下面二者之一。

**CH340 / COM5：**

```powershell
python .\serial-agent\wheel_agent.py --port COM5 --baud 230400 --enable-stream --backend http://127.0.0.1:8082
```

**换为 STC / COM6 后：**

```powershell
python .\serial-agent\wheel_agent.py --port COM6 --baud 230400 --enable-stream --backend http://127.0.0.1:8082
```

`--baud` 与默认值一致，显式列出便于核对。`--enable-stream` 启动时只发送一次 `A0 AC 08 BA 66` 开启遥测，后续 CW1 报文调整模式/周期；不会发送电机校准、转动或停机命令。板卡中途断电重启后如未输出，重启采集程序再次发送开启命令。

通过条件：

1. 终端显示 `COM5@230400` 或 `COM6@230400` 及 `.dcw` 记录路径。
2. 约每 5 秒的报告中“接收”“上传”持续增加，无效候选和未上传丢弃不持续增长。
3. 网页为“正在接收”、来源“串口采集”，设备时间更新，通道值可见。
4. 能通过后续配置确认验证双向通信。

上传短时落后于接收可能来自批处理或网络延迟；只有文件增大、有效帧为零时要查协议和 CRC。静止时角速度可接近零，不要求所有通道为零。

需要串口助手诊断时，先停 Python，按 230400/8N1 打开对应端口，**十六进制**发送 `A0 AC 08 BA 66`，不要发这段文字的 ASCII。可能先收到 `A0 AC 08 BA 99` 命令回显，它不是遥测帧；新遥测魔数为 `44 43 57 31`（DCW1）。诊断后关闭助手再运行代理；旧 `parse_debug.py` 不适用新协议。

## 10. 确认压缩与遥测周期控制生效

### 10.1 配置闭环

1. 网页选择 **RAW / 100 ms**，点击“应用配置”。
2. 保存后等待代理下发和板端回传。代理通常约每 2 秒取配置，实际受网络及调度影响。
3. 同时核对“设备已确认当前配置”、实际编码 RAW、实际周期 100 ms 和设备时间继续变化。
4. 切换 **AUTO / 100 ms** 再确认。AUTO 每帧尝试 ZRLE，没有收益时回退 RAW 属于正常行为。
5. 稳定后逐级测试 50、20、10 ms，范围为整数 10～1000 ms；观察缺口、错误、上传与控制状态。

保存成功只是后端接收了期望配置，必须等新遥测头确认板端实际值。历史回放不下发配置，也不作为实机配置确认。

网页周期控制的是遥测读取/输出节奏，不改变 FOC 中断频率或传感器硬件采样配置；同帧读取也不保证全部变量严格同步采样。配置在内存中保存，不作为永久 Flash 设置；板端和后端重启后重新核对。

### 10.2 看懂节省比例

某阶段 F 帧，编码载荷 P 字节，DCW1 整帧 W 字节：

```text
载荷节省       = (1 - P / (64 × F)) × 100%
同协议整帧节省 = (1 - W / (86 × F)) × 100%
W = P + 22 × F
```

RAW 一帧 20 字节头 + 64 字节数据 + 2 字节 CRC = 86 字节。全零 64 字节载荷可压为 1 字节、整帧 23 字节，这是边界示例，不是实机常态。

100 Hz RAW 为 8600 字节/秒，8N1 下约 86000 bit/s，占 230400 的 37.3%；这是带宽预算，不是实时性能实测。旧协议为 66 字节，页面整帧节省不能直接当成相对旧协议收益。

### 10.3 分段比较，不混用累计比例

页面比例是后端启动以来累计值，回放和之前模式也包含在内。实验每段在**配置确认后**记录起点，结束后记录终点：

```powershell
$before = Invoke-RestMethod http://127.0.0.1:8082/api/wheel/status
# 运行一段固定工况采集；结束时执行：
$after = Invoke-RestMethod http://127.0.0.1:8082/api/wheel/status
$frames = $after.acceptedFrames - $before.acceptedFrames
$wire = $after.wireBytes - $before.wireBytes
if ($frames -gt 0) { 100 * (1 - $wire / (86.0 * $frames)) }
```

期间不要重启后端；不同模式采用相同周期、相近时长和工况。可分别保存 RAW/AUTO 的 `.dcw` 与 CSV，并记录配置确认时间。

先静态验证链路，再按原板流程做可控运行实验；记录压缩率、缺口、延迟与控制时序。仅有压缩率不能证明控制实时性合格。

## 11. 通道含义与无损验证

| 通道 | 内容 | 单位与说明 |
|---|---|---|
| 1～3 | gyro_x/y/z | 原工程滤波角速度，°/s |
| 4～6 | angle_x/y/z | 原工程姿态角，° |
| 7～9 | wheel1/2/3_speed | 当前计算式对应 °/s；RPM = 数值 / 6 |
| 10～12 | wheel1/2/3_iq | 原 FOC Iq 数值，物理电流换算需按板卡标定确认 |
| 13 | battery_v | V |
| 14 | protect_flag | 状态值转为 float |
| 15～16 | rc_x/y | 原遥控输入单位 |

无损指 64 字节 float32 原始位模式经编解码完全一致，不等于传感器无误差、无丢帧或同步采样。负零、NaN/Inf 位模式可保留；网页和 CSV 的数值格式不适合独立证明位级一致。

Python 先筛选有效帧，Java 再整批校验/解压；每帧恢复 64 字节。CRC-16/CCITT-FALSE 用于检错，不纠错；坏帧被丢弃并重新同步，串口不自动请求重传。

已有 C/Python 测试包含 5004 组随机和特殊位模式。真机可在非电机运行的台架条件下使用已知向量，对比压缩前字节与解压后字节；曲线看起来相似不能替代位级验证。

## 12. 保存、停止与断网恢复

### 12.1 两类文件

- `.dcw`：代理记录收到的原始串口字节，包括杂字节/坏候选。默认位于执行命令目录的 `runtime\wheel-UTC时间.dcw`，用于完整记录和重新解析。
- CSV：网页导出当前会话最近最多 4000 帧。100 Hz 连续有效接收时约 40 秒，后端不是全程存档。

指定实验文件：

```powershell
python .\serial-agent\wheel_agent.py --port COM5 --baud 230400 --enable-stream --backend http://127.0.0.1:8082 --record .\runtime\COM5-test01.dcw
```

文件存在时拒绝覆盖，后续实验换新文件名；COM6 相应修改。切换采集会话、判定设备重启会清空最近样本缓存，后端关闭内存数据丢失，先导出所需 CSV。

### 12.2 停止

先导出 CSV，再在代理终端 Ctrl+C，保存记录路径；按原设备流程停机/断电，最后关闭上位机服务，需要换线时断电操作。

**Ctrl+C 只停止电脑采集，不是电机停机命令，也不保证板端关闭遥测。** 当前代理没有专门关闭遥测输出的选项，关闭网页同样不会让电机停机。

### 12.3 断网与回放

串口读取和 HTTP 上传分线程。断网时继续记录，网络重试；待传队列最多 100 批，满后“未上传丢弃”增加。当前重试项另在网络线程中，这不是可靠磁盘消息队列。

网络恢复后，先停止实时采集，再回放：

```powershell
python .\serial-agent\wheel_agent.py --replay .\runtime\COM5-test01.dcw --backend http://127.0.0.1:8082 --pace 0.2
```

回放用新会话上传整份文件有效帧，不是按帧断点续传；此前成功上传的内容可能重新计入累计统计。只能恢复电脑已收到且已记录的内容，不能恢复串口已丢失的数据。

## 13. 两台电脑传输

例：A 接 CH340/COM5；B 的局域网 IP 为 `192.168.1.20`，运行后端和网页。

1. B 按前述流程准备并启动服务。
2. 确认网络互通，B 允许 A 访问 8082；A 也看网页时需访问 8080。
3. A 安装 Python/串口依赖，在项目根目录执行：

```powershell
Test-NetConnection 192.168.1.20 -Port 8082
python .\serial-agent\wheel_agent.py --port COM5 --baud 230400 --enable-stream --backend http://192.168.1.20:8082
```

B 打开 `http://localhost:8080/wheel`，A 可开 `http://192.168.1.20:8080/wheel`。数据以压缩帧上传到 B，解压在 B 执行；配置从 B 经 A 到板端。

换 STC 时 A 改为 COM6，B 不需要另接 USB-TTL。一个后端对应一个动量轮数据源，避免多代理交错上传。本例按可控局域网使用，公网部署需另设计认证、加密和网络入口。

## 14. 实机验收记录

| 阶段 | 通过条件 | 保留证据 |
|---|---|---|
| 驱动/适配器 | 端口对应、230400 回环通过、信号电平已确认 | 型号、端口、电平说明/测量 |
| 软件回放 | 1000 帧、历史曲线、CSV 导出 | 终端输出与页面状态 |
| 固件构建 | 完整 Rebuild 成功、存储布局匹配 | 日志、版本、新 AXF 时间/摘要 |
| 下载 | 写入、校验成功，复位运行 | 探针/算法及下载日志 |
| 实时采集 | 接收上传持续增加、来源为串口 | 原始 `.dcw`、终端日志、CSV |
| 配置闭环 | RAW/100 ms、AUTO/100 ms 被新帧确认 | 实际模式、周期和时间 |
| 数据正确 | 量纲对应、已知向量位级一致 | 标定记录、字节对比 |
| 稳定性能 | 典型工况满足控制时序，错误/缺口可解释 | 分段统计、时序及运行记录 |

压缩在主循环原控制逻辑之后执行，DMA 忙则跳过遥测槽，不等待、不补发过期采样。序号缺口也可能来自 DMA 忙和调度延迟，不能直接作为网络丢包率。持续遥测也可能占用原校准应答的 DMA 时机，原校准按既有流程单独进行。

需在实物测量压缩最坏执行时间、主循环周期/抖动、FOC 中断时序、端到端延迟和实际工况压缩率。可使用 DWT 或 GPIO 配合示波器；软件桩测试和带宽预算不能替代实测。

## 15. 排错表

| 现象 | 检查方向 |
|---|---|
| 驱动已下载但没 COM5 | 完成安装、重插，查设备管理器和 USB 数据线；端口号可能变化 |
| COM 打不开 | 查端口和占用，关闭助手/旧代理 |
| 回环通过但接板无数据 | 查供电、程序运行、CN3 方向、GND、电平、TX/RX、开启命令 |
| 能收但配置不确认 | 查适配器 TX→PB11 下行、代理后端地址与网络；上行成功不代表下行正常 |
| `.dcw` 增大但有效帧为零 | 查是否仍为旧 0x23 固件、230400 参数、DCW1 魔数和 CRC；回显不是数据帧 |
| 接收增长但上传不增长 | 查 8082 接口、后端/代理 HTTP 日志，保留 `.dcw` |
| 网页打不开 | 查 Java/Node、启动日志、8080/8082 占用、dist 与网关依赖 |
| 动量轮 API 为 404 | 查新 JAR 与旧实例，不只看通用 health |
| AUTO 实际为 RAW | 无收益回退正常；实机 16 通道不等同零通道示例 |
| 无效候选或缺口持续增长 | 查线长、接地、供电、串口、主循环和 DMA；先增至 100 ms 定位 |
| C9511E/A9511E | 修复 MDK/ARMCC 产品授权识别，见 Keil 修订说明 |
| SWD 找不到器件 | 查兼容性、供电、地、VTref、脚序与速度；CN3-2 不是 3.3 V 参考 |
| 下载后异常/校准丢失 | 查型号、Flash 算法、擦除范围与原校准恢复流程 |
| 停采后电机仍转 | Ctrl+C 不控制电机，按原板流程停机 |
| 重启/新会话后曲线消失 | 最近样本是内存缓存；CSV 归档、`.dcw` 可回放 |

DCW1 为 20 字节头 + 1～64 字节载荷 + 2 字节 CRC，最大 86 字节；多字节整数和 float32 小端。头包含编码、通道数、长度、序号、毫秒、实际模式/周期和保留字段，每帧独立。

CW1 配置固定 8 字节：`43 57 01 mode period_lo period_hi crc_lo crc_hi`，RAW=0、AUTO=1，CRC 覆盖前 6 字节；后续遥测头确认应用状态，没有独立配置 ACK。
